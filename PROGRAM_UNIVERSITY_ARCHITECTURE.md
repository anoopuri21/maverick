# Program ⇄ UniversityPartner — Enterprise Architecture (DRY, Relationship-Driven)

Branch: `dev/overall-development`
Goal: **ek hi jagah data, baaki sab reference.** University details sirf ek baar fill karo; Program me dropdown/checkbox se select karo — kabhi re-type nahi. Navbar + detail dono relationship se derive hote hain.

---

## 1. Core principle: Single Source of Truth (DRY)

| Entity | Stored once in | Everything else |
|--------|---------------|-----------------|
| University (name, country, city, logo, website, description) | `university_partners` table | Program/Navbar **reference** by FK — never re-typed |
| Program (title, duration, content, JSON sections) | `programs` table | University link via pivot — never re-typed |
| Category (label, icon) | `program_categories` table | Program references by FK |

**Rule:** Koi bhi data jiski identity hai (university, program, category) = apna table. Koi bhi "belongs to" relation = FK. Kabhi kisi field me manually dusri entity ka naam/URL mat daalo — dropdown/checkbox se select karo.

---

## 2. Data model

```
program_categories (id, name, slug, icon, description, is_active)
        │ 1
        │
        N
programs (id, program_category_id FK, title, slug, duration, level,
          short_description, description, image_url, brochure_url,
          is_featured, is_active, sort_order,
          ...13 JSON content columns)   ← NO partner_university string, NO university JSON
        │ N
        │
       M─M via pivot
        │
        │ M
university_partners (id, name, country, country_code, city, latitude, longitude,
                     is_hub, logo_url, website_url, description, recognition,
                     sort_order, is_active)
                        ← NO programs JSON column

program_university_partner (program_id FK, university_partner_id FK,
                            is_primary, sort_order, timestamps)
```

### Relationships
```php
// Program
public function programCategory(): BelongsTo               // 1 category
public function universityPartners(): BelongsToMany(UniversityPartner::class)
    ->withPivot(['is_primary','sort_order'])->withTimestamps();

// UniversityPartner
public function programs(): BelongsToMany(Program::class)
    ->withPivot(['is_primary','sort_order'])->withTimestamps();

// ProgramCategory
public function programs(): HasMany
```

### `partner_university` + `university` JSON → removed
- `partner_university` string column: **drop** (ab pivot se).
- `university` JSON column: **drop** (ab `UniversityPartner` is the source; long-form "About" = `university_partners.description`).
- Any migration preserves old data into the pivot first.

## 3. Why this is "simple" (what you asked)

**Enter once → reusable everywhere:**
- Admin ek `UniversityPartner` banata hai (Dubai University) — details fill.
- Program form me **`CheckboxList`/`BelongsToManyMultiSelect`** of universities → sirf tick karo, kuch re-type nahi.
- Navbar, detail page, listing — sab `program->universityPartners` / `university->programs` se derive. **Koi hardcode nahi.**

## 4. Admin UX (Filament v3.3) — the key simplicity

### ProgramResource
```php
// Replace partner_university TextInput + university JSON repeater with:
CheckboxList::make('universityPartners')
    ->relationship('universityPartners', 'name')
    ->columns(2)
    ->label('Offered by Universities')
    ->helperText('Select universities offering this program — no need to type names.');
```
→ Admin program banate waqt bas universities **tick** karta hai.

### UniversityPartnerResource
```php
// Replace freeform programs Repeater with:
CheckboxList::make('programs')
    ->relationship('programs', 'title')
    ->columns(2)
    ->label('Programs Offered');
```
→ University edit pe bas programs tick karo.

- **BelongsToManyRelationManager** (`ProgramResource → relationManagers`) pe pivot fields edit karo. Default use ke liye skip — sirf link + checkbox enough.

## 6. URL / detail per-university (scenario 4)

**URL scheme (recommended, SEO-clean):**
```
/programs/{program:slug}/{university:slug?}
```
- `/programs/bsc-business-management` → generic (uses first/primary linked university OR brand-neutral).
- `/programs/bsc-business-management/dubai-university` → detail scoped to Dubai University.

**Controller:**
```php
public function show($programSlug, $universitySlug = null)
{
    $program = Program::whereSlug($programSlug)->active()
        ->with('universityPartners')->firstOrFail();
    $university = $universitySlug
        ? $program->universityPartners->firstWhere('slug',$universitySlug)
        : $program->universityPartners->first();   // default primary
    return view('programs.detail', compact('program','university'));
}
```
- Detail page "About the University" renders `$university` (single, correct one).
- Navbar link to a specific university's program → includes the university slug; clicking it opens that university's scoped detail.
- **Program content is shared (single source); only university branding/identity changes per URL.**

## 7. Migration & data seeding plan

1. `create_program_university_partner_table` (FKs + `is_primary`, `sort_order`).
2. `university_partners` → add `slug` (unique) if not present.
3. Migration script:
   - Parse each `Program.partner_university` string → find/create `UniversityPartner` → attach pivot.
   - Parse old `university` JSON → merge description into the matched partner.
   - Drop `partner_university` + `university` columns after data safe.
4. Seeder: categories + programs + university partners + pivot links.
